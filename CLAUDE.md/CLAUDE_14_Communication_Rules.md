# 14. Communication Rules

## Purpose

This section defines how engineering progress, implementation decisions, risks, and requests for clarification should be communicated throughout the development of CodeSense AI.

Communication should be clear, concise, factual, and engineering-focused.

---

# Communication Principles

Every response should be:

- Accurate
- Actionable
- Concise
- Professional
- Evidence-based

Avoid unnecessary conversational filler.

---

# Default Response Structure

When completing an implementation, respond using the following structure.

## Summary

Provide a brief explanation of what was implemented.

## Files Created

List every newly created file.

## Files Modified

List every modified file.

## Verification

Explain how the implementation was verified.

## Risks or Limitations

Identify any remaining assumptions, risks, or known limitations.

## Recommended Next Step

Recommend the next logical engineering task.

---

# Explaining Decisions

When explaining engineering choices:

- State the decision.
- Explain the technical reasoning.
- Reference the applicable architecture or standard where relevant.
- Avoid unnecessary theory.

Focus on practical engineering reasoning.

---

# Clarification Requests

Request clarification only when:

- Requirements conflict.
- Architecture would need to change.
- Security implications are unclear.
- Critical information is missing.
- Multiple valid implementations exist with materially different outcomes.

When asking for clarification:

- Explain why clarification is needed.
- Present available options if appropriate.
- Do not guess.

---

# Assumptions

If a safe assumption is required:

- Clearly identify it as an assumption.
- Minimize its impact.
- Prefer conservative decisions.

Never present assumptions as confirmed facts.

---

# Progress Reporting

After significant work, communicate:

- What was completed.
- What remains.
- Any blockers.
- The next recommended milestone.

---

# Error Reporting

When errors occur:

- Explain the issue.
- Identify the likely cause.
- Recommend corrective actions.
- Avoid speculation beyond available evidence.

---

# Final Principle

Communicate like a senior software engineer collaborating with another engineer.

The objective is to improve understanding, reduce ambiguity, and keep development moving efficiently.
